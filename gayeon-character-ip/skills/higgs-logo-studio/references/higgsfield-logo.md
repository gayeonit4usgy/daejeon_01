# 힉스필드 실행 규칙 — 로고용

이 문서의 모델·파라미터·비용은 **2026-07 기준 실측값**이다. 플랫폼은 계속 바뀌므로 **문서와 실제가 다르면 실제가 맞다.** 생성 전에 `models_explore`로 현재 파라미터를 확인한다.

## 시작 전 3가지

1. **연결 확인** — 힉스필드 도구가 없으면 `tool_search`로 로드. 그래도 없으면 커넥터 연결을 안내하고, 그동안 프롬프트와 설계안을 글로 넘긴다(사용자가 힉스필드 웹에 붙여넣을 수 있다).
2. **잔액** — `balance`. 시안 4장에 약 9크레딧이 든다.
3. **비용** — `get_cost: true`로 프리플라이트해서 기획 요약에 함께 말한다.

## 모델 배치

| 용도 | 모델 | 이유 |
|---|---|---|
| **시안 2장 (벡터 계열)** | `recraft_v4_1` + `model_type: "vector"` | 태그가 `logos, icons, vector, brand, palette`. 로고 문법에 가장 가깝다 |
| **시안 2장 (타이포 계열)** | `gpt_image_2` | 글자 정확도가 강하다. 브랜드명이 들어간 시안은 이쪽 |
| **기존 로고 수정** | `gpt_image_2` (필수) | **Recraft는 레퍼런스 이미지를 못 받는다.** 수정 경로에서는 선택지가 없다 |
| 확정본 고해상 | `gpt_image_2` (`resolution: "4k"`, `quality: "high"`) | 확정된 1장에만 쓴다 |
| 배경 투명화 | **`scripts/logo_qa.py` (코드, 크레딧 0)** | 아래 참조 |
| 코드 투명화 실패 시 폴백 | `remove_background` 도구 | 크레딧 소모 + 로고 내부 흰색이 뚫릴 수 있다 |

### 파라미터 실측

**`recraft_v4_1`**
- `model_type`: `standard` / **`vector`** / `utility` / `utility_vector` — 로고는 `vector`
- `colors`: HEX 배열 최대 10개 (`#RRGGBB`, 알파 없음) — **팔레트를 여기서 잠근다.** 프롬프트로 색을 부탁하는 것보다 정확하다
- `background_color`: `#RRGGBB` 또는 null — **`"#FFFFFF"`로 고정한다.** 투명화 스크립트가 안정적으로 작동한다
- `resolution`: `1k` / `2k`
- 비율: `1:1` 포함 지원
- **`medias` 미지원** — 레퍼런스 이미지를 못 받는다. 새로 만들기 전용이다
- 비용: 1k 기준 **2.5크레딧**

**`gpt_image_2`**
- `resolution`: `1k` / `2k` / `4k`, `quality`: `low` / `medium` / `high`
- 탐색은 `1k` + `medium`, 확정본만 `4k` + `high`
- `medias`: role `image` 지원 → **기존 로고 수정에 쓸 수 있다**
- 비율: `1:1` 포함 지원
- **투명 배경 파라미터는 없다.** OpenAI 본 API와 달리 힉스필드 경유로는 `background: transparent`를 못 준다. 투명은 코드로 만든다
- 비용: 1k/medium 기준 **2크레딧**

## 로고 생성 공통 설정

- **비율은 `1:1`.** 로고는 정사각 캔버스에서 판단한다. 나중에 잘라 쓰는 건 쉽지만, 늘여 쓰는 건 안 된다
- **배경은 순백 플랫.** 판단에 배경이 개입하면 안 되고, 투명화가 쉬워진다
- `count`는 모델당 2. 4장을 한 모델에서 뽑지 않는다 (모델마다 로고 해석이 다르고, 그 차이가 곧 선택지다)

## 기존 로고를 다룰 때 — 업로드 경로

**채팅에 첨부된 파일을 힉스필드는 읽지 못한다.** 로컬 경로를 `medias`에 넣으면 실패한다. 경로는 둘뿐이다:

1. 사용자 로컬 파일 → **`media_upload_widget`** (type=image)으로 다시 받는다. 이유를 말한다: "채팅에 올려주셨지만 생성 서버가 채팅 첨부를 못 읽어서, 한 번만 더 부탁드립니다"
2. 웹 URL → `media_import_url`

### element로 잠글지, medias로 넘길지

- **단순 수정 (색만·글씨만·정리)** → `gpt_image_2`의 `medias`에 role `image`로 원본을 직접 넘긴다. 가장 정확하다
- **여러 번 변주해야 함** → `show_reference_elements` `action=create`로 element를 만들고, 프롬프트 문자열 안에 `<<<element_id>>>`를 넣는다. `medias` 배열에 넣지 않는다 — placeholder가 주입을 처리한다. 워크스페이스에 남아서 후속 작업에 재사용된다

**사용자에게 `<<<UUID>>>`나 모델 ID 같은 내부 표기를 노출하지 않는다.** 말할 때는 "원본 로고를 기준으로 잡아두었습니다" 정도로 푼다.

## 생성 루틴

1. `get_cost: true` 프리플라이트 → 예상 크레딧을 기획 요약에 포함
2. 생성 (Recraft 2 + GPT Image 2 2)
3. `job_display`로 결과 표시 — **job ID 하나당 호출 한 번**
4. 응답의 `adjustments`는 반영하고, `recovery_tool`이 돌아오면 설명 없이 즉시 호출한다
5. 크레딧 부족 → `show_plans_and_credits`로 안내. 대신 결제하거나 무단 진행하지 않는다

## 하지 않는 것

- **Marketing Studio 계열(`marketing_studio_image` / `ms_image`) 사용.** 제품 URL에서 광고 시안을 자동 생성하는 파이프라인이라 로고와 목적이 다르다. 도구 설명이 "product/ads면 marketing_studio가 기본"이라고 유도해도 따르지 않는다
- Recraft로 기존 로고 수정 시도 (레퍼런스를 못 받는다 — 조용히 무시되고 엉뚱한 게 나온다)
- 로컬 파일 경로를 `medias`에 전달
- 같은 프롬프트 3회 이상 재시도 — 2회 실패하면 프롬프트를 고치거나 모델을 바꾼다
- 실패·비용 문제를 사용자 몰래 처리 — 크레딧이 걸린 일은 전부 보고한다
