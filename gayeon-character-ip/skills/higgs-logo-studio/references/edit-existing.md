# 기존 로고 고치기

Q1에서 "있는 로고 고치기"를 골랐거나, 사용자가 로고 이미지를 올리며 시작했으면 이 흐름이다.

## 왜 진단이 먼저인가

사용자는 "로고 좀 고쳐줘"라고 말하지만, **뭘 고쳐야 하는지는 모른다.** 안다면 진작 고쳤을 것이다. 대개 "뭔가 촌스러운데 뭔지 모르겠다"는 상태로 온다.

여기서 "어디를 고칠까요?"라고 되물으면 대화가 멈춘다. 그래서 순서가 뒤집힌다: **스킬이 먼저 진단하고, 사용자는 진단 결과에서 고른다.** 고르는 건 초보자도 할 수 있다.

## 0단계 — 원본 받기

**채팅 첨부는 힉스필드가 못 읽는다.** `media_upload_widget`(type=image)으로 다시 받는다. 이유를 말한다 — 사용자는 방금 올렸는데 또 올리라니 이상하게 느낀다.

로컬 파일이 필요한 건 힉스필드만이 아니다. **진단 스크립트도 파일이 필요하다.** 사용자가 채팅에 올린 파일은 `/mnt/user-data/uploads/`에 있으므로 스크립트는 그 경로를 쓰고, 힉스필드 생성용으로만 위젯 업로드를 받는다.

**남의 로고는 다루지 않는다.** 올라온 것이 널리 알려진 기업 로고면 수정하지 않고 그 이유를 말한다. 사용자 본인이나 회사의 로고라는 전제에서만 진행한다.

## 1단계 — 진단 (스킬의 일, 크레딧 0)

먼저 원본에 검수 스크립트를 돌린다. **말로 하는 비평보다 눈으로 보는 증거가 세다.**

```bash
python scripts/logo_qa.py /mnt/user-data/uploads/<원본> --outdir /home/claude/diag --name 원본진단
```

나온 검수 시트를 사용자에게 **보여주면서** 진단한다. "32px에서 안 읽힙니다"라고 말하는 것과, 32px로 줄인 실제 이미지를 보여주는 것은 설득력이 다르다. 초보자는 후자에서 처음으로 "아, 이래서 이상했구나"를 느낀다.

`logo_qa.py`가 자동 판정하는 3가지:
1. **작은 크기** — 32px 파비콘에서 형태가 남는가
2. **흑백** — 색을 빼도 구분되는가
3. **어두운 배경** — 다크모드·밤 배너에서 보이는가

스킬이 눈으로 보는 3가지:
4. **기억성** — 요소가 몇 개인가. 3개를 넘으면 기억에 안 남는다
5. **독창성** — 업종 상투 아이콘인가 (카페=컵, 교육=학사모, IT=지구본)
6. **정돈** — 자간·정렬·굵기가 흔들리는가. 초보자 로고에서 가장 흔한 문제이자, 사용자가 "촌스럽다"고 느끼는 실제 정체다

**진단은 3~4줄로 짧게, 근거와 함께.** 장문의 비평은 사용자를 방어적으로 만든다. 그 로고는 대개 사용자가 직접 만들었거나 돈을 주고 산 것이다. 문제를 지적하되 사람을 지적하지 않는다.

## 2단계 — 질문 4개

Q1은 이미 지났다. 진단을 끝낸 뒤 묻는다.

### Q2 — 뭐가 걸리세요? (진단 기반)

선택지를 **진단 결과에서 만든다.** 고정 목록이 아니다. 실제로 발견된 문제만 올린다.

> **어떤 게 제일 걸리세요?**
> - 작게 하면 안 보여요 *(진단에서 발견됨)*
> - 너무 복잡해요 *(요소 5개 발견)*
> - 색이 마음에 안 들어요
> - 느낌이 우리랑 안 맞아요
> - **잘 모르겠어요 — 진단대로 해주세요** ← 이 선택지가 제일 중요하다

마지막 선택지를 반드시 넣는다. 초보자는 자기 로고의 문제를 언어화하지 못하고, 그게 정상이다. 진단을 이미 했으니 그대로 따르면 된다. 이 선택지가 없으면 사용자는 아무거나 찍는다.

### Q3 — 어디에 쓰세요?

새로 만들기와 동일하다 (간판·인쇄 / 온라인·SNS / 앱 아이콘 / 포장). **원본을 만들 때 용도를 고려 안 했을 가능성이 높고, 그게 문제의 원인인 경우가 많다.** 앱 아이콘이 필요한데 워드마크만 있는 식이다.

### Q4 — 어느 정도로 바꿀까요?

> - **살짝 정리** — 보면 같은 로고인 걸 알 수 있게. 간판·명함을 이미 만들었다면 이쪽
> - **확 바꾸기** — 정신만 남기고 새로

**이 질문이 중요한 이유는 매몰 비용 때문이다.** 이미 간판을 달고 명함을 찍었으면 로고가 바뀌는 순간 전부 다시 만들어야 한다. 초보자는 이 계산을 안 하고 "확 바꿔주세요"라고 했다가 나중에 후회한다. 선택지에 **판단 기준을 함께 적어서** 스스로 계산하게 한다.

## 3단계 — 수정안 생성

`references/higgsfield-logo.md`를 읽고 실행한다. **Recraft는 못 쓴다** — 레퍼런스 이미지를 못 받는다. `gpt_image_2` 단독이다.

### 살짝 정리

원본을 `medias`(role `image`)로 넘기고, **바꿀 것만 명시하고 나머지는 지킬 것을 명시한다.**

```
Keep the existing symbol shape, composition, and overall proportions of the reference 
logo. Change only: [바꿀 것]. Preserve the original color relationship. 
Flat vector artwork on pure white background. No mockup, no 3D, no shadow, no extra text.
```

"고쳐줘"라고만 하면 모델은 전부 새로 그린다. **지킬 것을 말해야 지킨다.**

### 확 바꾸기

원본에서 **무엇을 살릴지 먼저 확정하고**(대개 색 또는 형상의 핵심 아이디어 하나), 그것만 계승해 새로 설계한다. 이때는 `references/logo-grammar.md`의 도출 규칙을 새로 만들기와 동일하게 적용한다. 원본은 참고일 뿐 기준이 아니다.

4장을 뽑되, **"살짝 정리"를 골랐어도 4장 중 1장은 조금 더 과감한 안을 섞는다.** 사용자가 안전한 선택지만 보면 비교 기준이 없어서 판단을 못 한다. 다만 그 1장이 무엇인지는 밝힌다.

## 한글이 있는 로고를 수정할 때 — 함정

**원본에 한글이 있으면 재생성 과정에서 글자가 깨진다.** 이건 예외가 아니라 기본값이다.

가장 안전한 접근:
1. **심볼만 수정하고 글자는 손대지 않는다.** 프롬프트에 `keep the existing text exactly as in the reference, do not redraw the letters`를 넣되, 이래도 모델이 글자를 다시 그리는 경우가 많으므로 **결과물의 글자를 매번 검수한다** (`references/korean-type.md`)
2. 글자가 계속 깨지면 → **심볼만 생성하고, 원본의 글자 부분을 그대로 살려 조립**하도록 안내한다. 파워포인트로 충분하다
3. 원본 글자 자체가 문제였다면(폰트가 촌스러움) → 심볼만 새로 만들고 **추천 폰트로 글자를 새로 얹는 것**이 정답이다. AI에게 한글 로고 타이포를 맡기는 것보다 항상 낫다

## 4단계 — 선택 → 다듬기 → 마무리

새로 만들기와 동일하다. SKILL.md의 "확정 → 마무리 세트"로 돌아간다.

**한 가지 추가**: 수정 경로에서는 **원본과 최종본을 나란히** 보여준다. 무엇이 좋아졌는지 사용자가 눈으로 확인해야, 이미 있던 로고를 바꾸는 결정에 확신을 갖는다. 그리고 진단에서 지적한 문제가 실제로 해결됐는지 `logo_qa.py`를 최종본에도 돌려 시트로 증명한다.
