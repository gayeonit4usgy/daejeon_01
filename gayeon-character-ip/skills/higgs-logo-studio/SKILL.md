# 로고 스튜디오 — 질문 4개로 끝내는 로고

## 이 스킬이 있는 이유

인터넷에 도는 로고 프롬프트들은 하나같이 이렇게 묻는다: `[산업] [타깃] [브랜드 성격] [핵심 메시지] [선호 스타일: 워드마크/모노그램/엠블럼/추상형] [선호 색상]`.

**이 빈칸을 채울 수 있으면 이미 초보자가 아니다.** 동네 카페 사장님에게 "브랜드 성격이 뭔가요"라고 물으면 대화가 거기서 멈춘다. 그래서 이 스킬의 일은 로고를 그리는 것이 아니라, **빈칸을 사용자 대신 채우는 것**이다. 사용자에게는 답할 수 있는 것만 묻는다.

원칙은 하나다. **말로 물으면 못 답하지만, 보여주고 예를 들면 고른다.** 질문 설계 전체가 여기서 나온다.

## 전체 흐름

```
새로 만들기:  Q1 경로 → Q2 이름+한 줄 → Q3 사용처 → Q4 느낌
              → [스킬이 로고 타입·색·폰트 확정 + 근거 고지 + 크레딧 고지]
              → 시안 4장 → 사용자가 1장 선택 → 다듬기 → 확정 → 마무리 세트

고치기:       Q1 경로 → 원본 업로드 → [스킬이 6기준 진단]
              → Q2 뭐가 걸리는지(진단 기반) → Q3 사용처 → Q4 변경 강도
              → 수정안 4장 → 선택 → 다듬기 → 확정 → 마무리 세트
```

질문은 한 번에 하나씩 간다. 네 개를 한꺼번에 쏟으면 초보자는 폼 작성처럼 느끼고 도망간다. 선택지 버튼 도구가 있으면 쓴다 — 타이핑이 적을수록 좋다.

## Q1 — 어느 쪽인가

> **새로 만드시나요, 지금 있는 로고를 고치시나요?** (새로 만들기 / 있는 로고 고치기)

"고치기"면 `references/edit-existing.md`를 읽고 그쪽 흐름으로 간다. 이 문서의 Q2~Q4는 새로 만들기용이다.

사용자가 이미 로고 이미지를 올리며 시작했으면 이 질문을 건너뛴다 — 답이 이미 나와 있는 질문은 하지 않는다.

## Q2 — 이름과 한 줄 (유일한 자유 입력)

> **브랜드 이름과, 뭐 하는 곳인지 한 줄만 알려주세요.**
> (예: "오빠두 — 직장인에게 엑셀을 가르치는 교육 채널")

이게 이 스킬에서 사용자가 타이핑하는 유일한 지점이다. 여기서 산업·타깃·톤을 **스킬이 추론한다.** 되묻지 않는다. 한 줄이 짧아도 괜찮다 — 부족한 건 추론하고, 추론했다는 사실만 나중에 한 줄로 밝힌다.

이름에서 바로 확정되는 것들:
- **글자 수** → 로고 타입 후보를 좁힌다 (아래 도출 규칙)
- **한글/영문/혼용** → 한글이 들어가면 `references/korean-type.md`를 읽는다. 한글 로고는 렌더링 리스크가 따로 있다
- **이니셜** → 모노그램 가능 여부

## Q3 — 어디에 쓰는가

> **주로 어디에 쓰실 건가요?** (복수 선택 가능)
> 간판·인쇄물 / 온라인·SNS / 앱 아이콘·프로필 / 상품 포장·스티커

용도를 묻는 이유는 취향 조사가 아니라 **물리적 제약을 받아내기 위해서**다. 초보자는 "예쁜 로고"를 원한다고 말하지만, 실제로 그를 곤란하게 만드는 건 간판에서 안 읽히거나, 앱 아이콘으로 줄이면 뭉개지는 로고다. 이 답이 로고 타입을 결정한다.

## Q4 — 어느 느낌인가

> **어느 쪽 느낌이 좋으세요?**
> - **깔끔·정돈** (애플, 무신사 같은 계열)
> - **따뜻·손맛** (동네 베이커리, 공방 계열)
> - **고급·클래식** (호텔, 주얼리 계열)
> - **재미·개성** (배달의민족 계열)

**참조 브랜드가 이 질문의 핵심 장치다.** "미니멀/럭셔리/대담함" 이라고만 쓰면 초보자는 단어의 뜻은 알아도 그게 자기 로고에서 뭘 의미하는지 모른다. 아는 브랜드를 하나 붙이면 감각이 즉시 전달된다.

**단, 참조 브랜드는 사용자와 감각을 맞추는 언어일 뿐이다.** 프롬프트에 브랜드명을 넣거나("make it look like Apple's logo"), 기존 로고의 형태를 모방하지 않는다. 남의 상표를 닮은 로고는 사용자에게 법적 위험을 안기는 것이지 서비스가 아니다. 프롬프트에는 그 계열의 **디자인 속성**(기하학적 단순함, 넉넉한 여백, 산세리프 등)으로 번역해서 넣는다.

## 질문이 끝나면 — 스킬이 확정한다

Q2·Q3·Q4의 답으로 **로고 타입·색·폰트를 스킬이 직접 정한다.** 이건 사용자에게 묻지 않는다. 판단 근거는 `references/logo-grammar.md`에 있고, 생성 전에 반드시 읽는다.

핵심 도출 규칙만 옮기면:

| 조건 | 귀결 |
|---|---|
| 앱 아이콘이 용도에 있음 | 워드마크 탈락. 정사각형 안에서 읽히는 심볼·모노그램 필수 |
| 이름이 길다 (4단어 / 한글 6자 이상) | 워드마크 부적합 → 모노그램 또는 심볼+워드마크 조합 |
| 간판이 용도 | 멀리서 읽혀야 함 → 굵은 획, 얇은 세리프 탈락 |
| 포장·스티커·자수 | 단색 재현 → 그라데이션·그림자·디테일 최소화 |
| 온라인·SNS만 | 제약이 가장 느슨함 → 표현 폭을 넓게 |

확정한 내용은 **생성 직전에 한 화면으로 요약해 보여준다**: 로고 타입과 그렇게 정한 이유 한 줄, 색(HEX), 폰트 방향, 시안 4장, 예상 크레딧(get_cost). 사용자가 여기서 "아니 그건 아닌데"라고 할 여지를 남기되, **승인을 기다리지 않고 같은 턴에서 바로 생성으로 간다.** 이미지는 싸고, 사용자가 원한 건 결재 절차가 아니라 로고다. 잔여 크레딧이 모자랄 때만 멈춘다.

## 시안 4장 생성

`references/higgsfield-logo.md`를 읽고 실행한다. 배치는 이렇다:

- **Recraft V4.1 (`model_type: vector`) 2장** — 로고·아이콘·타이포에 특화됐고, `colors`로 팔레트를 HEX 단위로 잠글 수 있다
- **GPT Image 2 2장** — 타이포그래피와 글자 정확도가 강하다. 브랜드명이 들어간 시안은 이쪽이 안전하다

한 모델로 4장 뽑지 않는 이유는 **모델마다 로고 해석이 다르기 때문**이다. 두 모델을 섞으면 같은 크레딧으로 더 넓은 스펙트럼이 나오고, 초보자는 선택지가 벌어져 있을수록 자기 취향을 발견하기 쉽다.

4장은 **서로 다른 접근**이어야 한다. 같은 시안의 색만 바꾼 4장은 선택지가 아니라 1개다.

결과는 `job_display`로 하나씩 보여주고, **번호를 붙여** 고르게 한다. "1번이 마음에 드는데 색만 다르게" 같은 답이 나오면 그게 정상이다 — 다듬기 단계가 그걸 받는다.

## 다듬기

선택된 1장을 기준으로 사용자의 코멘트를 반영해 2~3장을 다시 뽑는다. 여기서도 묻지 않는다 — 사용자가 "좀 더 심플하게"라고 하면 그게 지시다.

**한글이 들어간 로고는 매번 글자를 검수한다.** 자모가 분리됐거나(ㅇ ㅏ), 없는 글자가 생겼거나, 획이 뭉갰으면 그 시안은 폐기하고 재생성한다. 로고는 글자 하나 틀리면 전체가 못 쓰는 물건이 된다. 2회 실패하면 `references/korean-type.md`의 우회 경로로 간다.

## 확정 → 마무리 세트

여기가 이 스킬이 다른 로고 프롬프트와 갈라지는 지점이다. **초보자는 "로고 이미지 1장"을 받으면 나중에 반드시 곤란해진다.** 명함에 얹으려니 흰 배경이 네모로 남고, 도장을 파려니 흑백이 없고, 인스타 프로필에 넣으려니 정사각형이 아니다.

확정본이 정해지면 `scripts/logo_qa.py`를 실행한다. 크레딧은 들지 않는다:

```bash
python scripts/logo_qa.py <확정본_이미지경로> --outdir <출력폴더> --name <브랜드명>
```

나오는 것:
- `*_transparent.png` — 투명 배경 (테두리 연결 판정이라 로고 안의 흰색은 보존된다)
- `*_mono.png` — 흑백 (도장·자수·단색 인쇄)
- `*_square.png` — 정사각형 (SNS 프로필·앱 아이콘)
- `*_qa_sheet.png` — **검수 시트**: 흰 배경 / 어두운 배경 / 흑백 / 32px 파비콘을 한 장에

**검수 시트를 반드시 사용자에게 보여주고 판정을 말로 옮긴다.** 스크립트가 경고를 뱉으면 그게 진짜 정보다:
- 어두운 배경에서 안 보임 → "밤 배너나 어두운 웹사이트에는 이 로고가 안 보입니다. 흰색 버전이 따로 필요합니다" (필요하면 흰색 버전을 추가 생성)
- 32px에서 뭉갬 → "파비콘·앱 아이콘 크기에서 형태가 사라집니다. 심볼만 쓰는 단순 버전이 필요합니다"
- 투명화 실패(배경이 그라데이션이라 코드가 못 뚫음) → 힉스필드 `remove_background`로 폴백하거나, 흰 배경으로 확정하고 그 사실을 알린다

투명화가 불가능한 시안이면 **흰 배경으로 확정하고 숨기지 않는다.** 되는 척하는 것보다 낫다.

## 전달

함께 넘긴다:
- 파일 세트 (`present_files`로 한 번에)
- **HEX 코드** — 나중에 명함·PPT·간판 업체에 넘길 값이다. 이게 없으면 사용자는 색을 눈대중으로 맞추게 된다
- **추천 폰트 이름** — 한글이면 무료 상업용 폰트로 (`references/korean-type.md`). 문서·자막에서 로고와 톤을 맞출 수 있다
- 스킬이 확정한 로고 타입과 그 근거 한 줄
- 검수 시트에서 나온 경고(있으면)

한 줄 덧붙인다: **AI 생성 로고는 상표 등록 전에 유사 상표 검색이 필요하다**는 것. 특허청 키프리스(kipris.or.kr)에서 무료로 볼 수 있다. 이건 겁주기가 아니라, 간판까지 달고 나서 알게 되면 늦기 때문이다.

## 전 경로 공통 원칙

- **전문 용어를 사용자에게 되던지지 않는다.** 워드마크·모노그램·엠블럼·커닝·자간은 스킬의 사고 도구지 사용자의 어휘가 아니다. 사용자에게 말할 때는 "글자만 있는 형태", "이름 앞글자를 딴 형태"처럼 푼다.
- **크레딧은 사용자 돈이다.** get_cost로 먼저 재고, 기획 요약에 함께 말한다. 시안 4장은 대략 9크레딧 선이다.
- **묻지 말고 정한다.** 이 스킬에서 허용된 질문은 Q1~Q4와 시안 선택뿐이다. 그 외의 결정(타입·색·폰트·구도·배경)은 근거를 갖고 스킬이 확정하고, 확정했다는 사실과 근거만 밝힌다. 초보자에게 결정을 되돌려주는 건 도움이 아니라 떠넘기기다.
- **남의 상표를 닮게 만들지 않는다.** 참조 브랜드는 대화용 언어일 뿐이다. 프롬프트에 브랜드명·기존 로고 형태를 넣지 않는다.
- **한 대화에 한 브랜드.** 크레딧과 혼입 사고 방지.
- 힉스필드 도구가 없으면 tool_search로 로드하고, 그래도 없으면 커넥터 연결을 안내한다. **연결이 없어도 프롬프트와 설계안을 글로 넘기는 것은 유효한 산출물이다** — 사용자가 힉스필드 웹에 직접 붙여넣을 수 있다.

## 하지 않는 것

- 사용자에게 브랜드 성격·로고 타입·타이포 방향을 묻는 것 (이 스킬의 존재 이유가 그걸 대신하는 것이다)
- 질문을 4개 초과로 늘리는 것
- 한글 글자 검수 없이 한글 로고를 전달하는 것
- 마무리 세트 없이 이미지 1장만 주는 것
- 로고가 들어간 포스터·광고·영상 만들기 (`higgs-ads-creator`의 일)
- 상표 등록 가능성 판단 — 스킬은 검색을 권할 뿐, 법률 판단은 하지 않는다
