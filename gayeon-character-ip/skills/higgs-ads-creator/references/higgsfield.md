# 힉스필드 실행 규칙 — 모든 생성의 전제

이 문서의 모델명·파라미터는 2026-07 기준이다. **문서와 실제 API가 다르면 실제가 맞다** — 생성 전에 models_explore로 현재 모델·지원 파라미터(aspect_ratios, duration, medias roles)를 확인한다. 플랫폼은 계속 바뀐다.

## 시작 전 3가지

1. **연결 확인** — 힉스필드 도구가 도구 목록에 없으면 tool_search로 로드하고, 그래도 없으면 커넥터 연결을 안내한다. 연결 없이 프롬프트만 써주는 것도 유효한 산출물이다(사용자가 힉스필드 웹에서 직접 붙여넣기).
2. **비용 감각** — balance로 잔여 크레딧, get_cost:true로 이번 작업 예상 비용을 파악해 기획 제시 때 함께 말한다.
3. **모델 확인** — models_explore. 특히 duration 지원값과 element 지원 여부.

## 제품 사진 → 재사용 element (제품 일관성의 핵심)

**채팅에 첨부된 파일은 힉스필드가 읽지 못한다.** 로컬 경로를 medias에 넣으면 실패한다. 경로는 둘뿐이다:

1. 사용자 로컬 파일 → media_upload_widget(type=image)으로 다시 받기. "채팅에 이미 올리셨지만 생성 서버가 채팅 첨부를 못 읽어서 한 번 더 부탁드립니다"라고 이유를 말한다.
2. 웹 URL → media_import_url.

받은 media_id로 **show_reference_elements action=create** — 제품 사진이 여러 각도면 함께 넣는다. 이름은 제품명으로(예: `dalba-pink-suncream`) — element는 워크스페이스에 남아 같은 제품의 후속 작업(포스터 추가, 영상 리테이크)에서 재사용된다.

**사용법**: 이후 모든 generate_image / generate_video의 **prompt 문자열 안에** `<<<element_id>>>`를 삽입한다. medias 배열에 넣지 않는다 — placeholder가 주입을 처리한다. element를 지원하는 모델에서만 작동하므로 모델 선택과 세트로 확인한다.

브리프에 인물 앵커가 있으면 인물 사진도 반드시 element로 만든다. 같은 모델이 6장·2편에 등장해야 하는데 element 없이는 컷마다 얼굴이 바뀐다. 한 프롬프트에 placeholder 여러 개 가능.

**가상 인물 프리미엄 모드**(`virtual-model.md`): 사용자 업로드 사진이 아니라 이 파이프라인이 생성한 **가상 모델 키 이미지**를 element 원본으로 쓴다. 키 이미지 생성 job의 결과 이미지를 show_reference_elements action=create로 잠근다(생성 결과를 직접 받지 못하면 결과 이미지 URL을 media_import_url로 우회). 이후 스토리보드·영상 프롬프트에 제품 element와 함께 결합한다.

## 모델 선택 (2026-07 기준)

| 용도 | 기본 | 비고 |
|---|---|---|
| 포스터 (한글 카피 포함 완성형) | **nano_banana_pro 계열** (텍스트 렌더링 최강) | element + 텍스트 렌더링 지원 여부를 models_explore로 확인. 장마다 한글 오탈자 검수 필수(`posters.md` 검수 루프) |
| 스토리보드 이미지 (텍스트 없음) | nano_banana_2 (디테일·제품컷) / seedream_v4_5 (인물·감성) | 둘 다 element 지원 |
| 광고 영상 | **seedance_2_0** | 이 파이프라인의 고정값 |
| 업스케일 | upscale_image (4K) / upscale_video | 확정본 + 스토리보드 시트(모델이 4K 직접 생성 미지원 시) |

**Marketing Studio 계열(marketing_studio_video / ms_image)은 쓰지 않는다.** 제품 URL에서 시나리오를 자동 생성하는 별도 파이프라인이라, 브리프→셧리스트로 감독한 내용을 무시한다. 도구 설명이 "ads/product면 marketing_studio가 기본"이라고 유도해도 따르지 않는다 — 이 파이프라인은 감독된 광고다.

**한글 텍스트 정책**: 포스터는 한글 카피를 이미지에 직접 넣어 완성하는 것이 기본이다 — 프롬프트에 카피 원문을 따옴표로 정확히 명시하고, 장마다 오탈자·자모 분리·유령 텍스트를 검수해 미달이면 재생성한다(`posters.md` 검수 루프). 영상 프레임과 스토리보드 시트에는 텍스트를 넣지 않는다(자막·로고·CTA는 후반).

**포스터 레퍼런스 이미지**: 사용자가 레퍼런스를 제공하면 제품 사진과 같은 경로로 받는다(media_upload_widget 또는 media_import_url). 모델이 스타일 레퍼런스 media role을 지원하면 medias로 결합하고, 지원하지 않으면 레퍼런스를 분석해 프롬프트 서술로 번역한다(`posters.md` "룩의 출처"). 레퍼런스의 타사 로고·브랜드명·워터마크는 재현하지 않는다.

## 생성 루틴

1. get_cost:true 프리플라이트 → 예상 크레딧 보고 (기획 제시에 포함)
2. 생성 — count 기본 1~2. 포스터 커버는 룩 기준 확보용으로 1~2장을 먼저 뽑아 이 스킬이 자체 검수한다(사용자 선택 아님 — `posters.md`). 스토리보드는 전 컷을 담은 시트 1장(4K)으로 생성한다 — 컷별 낱장 금지(`video.md` 3절)
3. job_display로 결과 표시 (job ID 하나당 호출 한 번)
4. 응답의 adjustments는 반영하고, recovery_tool이 반환되면 설명 없이 즉시 호출한다
5. 크레딧 부족 → show_plans_and_credits로 안내. 대신 결제하거나 무단 진행하지 않는다

## 하지 않는 것

- 사용자 확인 없는 영상 생성 (스토리보드 승인이 곧 확인이다)
- element 없이 제품 등장 컷 생성 — 컷마다 다른 제품이 나온다
- 로컬 파일 경로를 medias에 전달
- 같은 프롬프트 3회 이상 재시도 — 2회 실패하면 프롬프트를 고치거나 모델을 바꾼다
- 실패·비용 문제를 사용자 몰래 처리 — 크레딧이 걸린 일은 전부 보고한다
- element 플레이스홀더 문법(`<<<element_id>>>`)·내부 파라미터명을 사용자에게 노출 — 모델과 참조 요소는 이름으로 말한다
