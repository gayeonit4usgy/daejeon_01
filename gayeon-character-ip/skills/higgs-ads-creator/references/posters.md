# 포스터 6장 세트 — 한글 카피가 들어간 완성형

## 완성형이란 무엇인가

이 스킬의 포스터 산출물은 **한글 헤드라인·서브카피가 이미지 안에 완성되어 들어간 포스터**다. 사용자가 받아서 미리캔버스·포토샵을 열 필요 없이 그대로 카드뉴스·캐러셀·상세페이지에 올릴 수 있어야 한다. 텍스트 없는 제품 이미지는 이 파이프라인에서 미완성 산출물이다.

완성형의 기준 (베이커리 프로모션 포스터를 떠올려라 — "소금빵" 대형 헤드라인 + 손글씨 주석, "크루아상" 세리프 헤드라인 + 한 줄 서브카피, 배경색 위에 통통한 타이포로 얹은 "Cream Cheese Bagel" 스타일):

- **헤드라인이 화면의 주인공 중 하나다.** 제품 사진과 타이포가 하나의 레이아웃으로 설계된다. 사진 따로 + 글자 따로가 아니다.
- **위계가 명확하다.** 상단 소개 문구(작게) → 메인 헤드라인(가장 크게) → 서브카피·주석(작게) → 하단 정보(가장 작게)처럼, 읽는 순서가 크기로 표현된다.
- **카피는 짧다.** 메인 헤드라인 2~6자, 서브카피 15자 내외, 주석(화살표·손글씨 코멘트)은 5자 내외. 글자가 길수록 생성 모델의 오탈자 확률이 급등한다 — 짧은 카피는 디자인 원칙이면서 동시에 품질 관리 수단이다.

## 왜 6장이 세트인가

6장은 한국 커머스의 카드뉴스·인스타 캐러셀·상세페이지 상단 구간의 표준 서사 단위다. 각 장은 피드에서 **단독으로 멈춰 세울 수 있어야** 하고, 순서대로 넘기면 **하나의 설득**이 되어야 한다. 6장이 따로 놀면 카드뉴스가 아니라 이미지 6개다.

기본 서사 뼈대 (스타일이 달라도 유지):

| 장 | 역할 | 내용 | 카피 예시 구조 |
|---|---|---|---|
| 1 | 후킹 커버 | 핵심 혜택을 장면으로. 메인 헤드라인이 가장 크게 들어간다 | 소개 한 줄(작게) + 제품명/혜택 헤드라인(크게) |
| 2 | 공감 / 문제 | 브리프의 '타깃 + 순간' 재현. 제품 없이 상황만 | 공감 질문형 헤드라인 |
| 3 | 핵심 혜택 | 브리프의 헤드라인 혜택 **하나**. 제품 등장 | 혜택 헤드라인 + 서브 한 줄 |
| 4 | 증거 / 실연 | 눈에 보이는 차이. 전후 비교면 동일 조건(조명·각도) 필수 | 증거 수치·사실 헤드라인 (표시광고법 3칸 통과분만) |
| 5 | 디테일 | 제품 클로즈업 + 포인트 주석(화살표·손글씨 코멘트) | 특징 키워드 주석 2~3개 |
| 6 | 마무리 | 브랜드 무드 컷 + CTA | 브랜드명/슬로건 + CTA 한 줄 |

사용자가 용도를 특정하면(예: 상세페이지 상단 6컷) 뼈대를 조정하되, "장당 하나의 메시지" 원칙은 유지한다. 한 장에 셋을 넣으면 영이 전달된다.

## 룩의 출처 — 레퍼런스가 있을 때 / 없을 때

SKILL.md 0단계에서 물은 레퍼런스 질문의 답이 여기서 갈린다:

**레퍼런스가 있으면 — 레퍼런스가 룩의 기준이다.**

1. 레퍼런스 이미지를 직접 분석해 다섯 가지를 추출한다: ① 레이아웃(카피가 어디에, 어떤 크기 위계로 앉는가), ② 배경(단색/질감/그라데이션, 색상값), ③ 타이포 성격(세리프/산세리프/손글씨, 두께, 자간 느낌), ④ 조명·무드(따뜻함/차가움, 확산광/하드라이트), ⑤ 여백 운용.
2. 추출한 다섯 가지를 영문 프롬프트 언어로 번역해 6장 전체에 공통 적용한다.
3. 모델이 스타일 레퍼런스 media role을 지원하면(models_explore로 확인) 레퍼런스 이미지를 medias로 함께 결합한다. 지원하지 않아도 1~2의 프롬프트 번역만으로 진행한다 — 레퍼런스 결합은 보조 수단이지 필수 조건이 아니다.
4. **레퍼런스는 스타일 기준이지 복제 대상이 아니다.** 타사 로고·브랜드명·상호·워터마크·고유 캐릭터는 절대 재현하지 않는다. 레퍼런스의 카피 문구도 그대로 쓰지 않는다 — 카피는 언제나 이 브리프의 제품에서 나온다.

**레퍼런스가 없으면 — AI가 학습한 디자인 지식이 기준이다.**

되묻지 않는다. 브리프의 카테고리·브랜드 무드·타깃을 근거로, 학습된 상업 포스터 디자인 문법 중 최적을 직접 고른다. 카테고리별 검증된 출발점:

| 카테고리 | 기본 룩 |
|---|---|
| F&B·베이커리 | 따뜻한 크림/브라운 톤 배경, 제품 히어로 샷, 큼직한 라운드 산세리프 또는 손글씨 헤드라인, 포인트 주석 |
| 뷰티·스킨케어 | 밝은 확산광, 화이트/파스텔 미니멀 배경, 가는 세리프 헤드라인, 넓은 여백 |
| 테크·가전 | 다크 배경 + 고대비 림라이트, 볼드 산세리프, 스펙 키워드 주석 |
| 패션·라이프스타일 | 무드 사진 전면 + 상하단 밴드에 타이포, 세리프/산세리프 믹스 |
| 금융·앱·서비스 | 브랜드 단색 배경, 일러스트 or 목업, 볼드 헤드라인 중앙 배치 |

이 표는 출발점이지 규정이 아니다 — 브리프의 브랜드 무드가 다른 방향을 가리키면 그쪽을 따르고, 확정한 룩과 근거는 전달 시 한 줄로 밝힌다.

## 장당 산출물 = 카피 확정 → 카피 포함 이미지 프롬프트

**1) 장별 한글 카피를 먼저 확정한다 (내부 작업 — 사용자에게 묻지 않는다):**

```
장 N — [역할]
메인 카피: (한글, 2~6자 권장·최대 15자)
서브 카피: (한글, 15자 내외, 선택)
주석/포인트: (한글 5자 내외, 선택 — 5장 디테일 등)
위치·위계: (예: 상단 1/3 중앙 정렬, 메인 > 서브 3:1)
법적 표기: (해당 시 — 광고 표기, 기능성 심사필 문구 등 브리프 legal 승계)
```

카피는 브리프의 대사 후보·리뷰 반복 어휘에서 가져온다 — 판매자 카피가 아니라 고객의 언어로. 최상급·효능 표현은 브리프의 표시광고법 3칸을 통과한 것만 쓴다. 이 카피 기록은 전달 시 "장별 카피 기록"으로 함께 준다(수정·법무 확인용).

**2) 이미지 프롬프트 (영문 서술 + 한글 카피 원문 삽입):**

- 장면·조명·구도·스타일은 영문으로 서술하되, **넣을 한글 카피는 따옴표로 원문 그대로 삽입**하고 위치·크기·타이포 성격을 지정한다. 예:

```
Korean bakery promotional poster, warm cream background, freshly baked salt bread
as hero centerpiece, soft window light. Large Korean headline text "소금빵" in bold
rounded sans-serif at top center, small Korean subtitle "바다 소금을 뿌린 숙성빵" above
it in lighter weight, two small handwritten Korean annotations "겉은 바삭" and
"속은 촉촉" with thin arrows pointing to the bread. All Korean text must be
rendered accurately, exactly as written, with correct Hangul letterforms.
<<<product-element-id>>>
```

- 프롬프트 끝에 한글 정확성 지시를 항상 붙인다: "All Korean text must be rendered accurately, exactly as written, with correct Hangul letterforms. No extra text, no gibberish characters."
- 카피 외의 텍스트가 생기지 않도록 negative 지시를 유지한다(no watermark, no random text).
- 선택된 스토리(2단계)와 표현 스타일(3단계)이 6장 전체를 통제한다: 공통 팔레트 3색(주·보조·강조), 공통 광원 방향, 공통 타이포 성격, 제품 등장 각도의 일관성. 이 네 가지가 흔들리면 캠페인이 아니라 잡동사니로 보인다.
- 제품 등장 장(1·3·4·5)은 element 결합 필수(`higgsfield.md`). 분위기 장(2·6)은 선택.
- 인물이 등장하면 6장에서 같은 인물이어야 한다 — 인물 외형 서술을 프롬프트 간 복붙하고, 가능하면 인물도 element로 잠근다.
- **실물 사진의 화질·각도·장수가 부족해도 사용자에게 추가 사진을 요구하지 않는다.** element 결합 상태에서 조명·배경·구도를 프롬프트로 새로 설계해 메운다. 사진에 없는 제품의 면이 화면 주인공이 되는 구도는 피한다 (SKILL.md 0단계 "재료가 부족할 때").

**모델 선택**: 한글 텍스트가 들어가는 포스터는 **텍스트 렌더링에 가장 강한 모델(nano_banana_pro 계열)이 기본값**이다 (`higgsfield.md`). models_explore로 현재 지원 모델을 확인하고, element와 텍스트 렌더링을 모두 지원하는 모델을 고른다.

## 한글 검수 루프 — 완성형의 품질 관문

생성 모델의 한글 타이포는 불안정하다. 그래서 **장마다 검수하고, 미달이면 재생성한다.** 검수 없는 전달은 금지다.

각 장 생성 직후 이미지를 직접 보고 확인한다:

1. **오탈자** — 카피 원문과 한 글자라도 다른가 (예: "소금빵"→"소곰빵")
2. **자모 분리·깨진 글자** — ㅅㅗㄱㅡㅁ처럼 풀어지거나 획이 뭉개진 글자
3. **유령 텍스트** — 요청하지 않은 글자·외계어·워터마크가 생겼는가
4. **레이아웃** — 카피가 지정 위치에, 지정 위계(크기 순서)로 앉았는가. 제품을 가리지 않는가
5. **잘림** — 카피가 프레임 밖으로 잘리지 않았는가

처리 규칙:

- 1~3번 미달 → 재생성. 같은 프롬프트 재시도는 1회까지, 그래도 실패하면 프롬프트를 고친다: 카피를 더 짧게 줄이거나, 폰트 서술을 단순화하거나(손글씨 → 볼드 산세리프), 텍스트 요소 수를 줄인다(주석 3개 → 1개). 같은 프롬프트 3회 이상 금지는 `higgsfield.md` 그대로.
- 4~5번 미달 → 위치·여백 지시를 강화해 재생성.
- 재시도 한도까지 특정 카피가 계속 깨지면: 그 장만 해당 카피를 뺀 클린 버전으로 생성하고, 전달 노트에 "이 장의 '○○' 문구는 생성 한계로 미포함 — 카피 기록의 위치 스펙대로 후반에서 얹으면 완성됩니다"라고 명시한다. 완성형이 원칙이지만, 오탈자 포스터를 완성형이라고 전달하는 것이 최악이다.

## 생성 순서 — 커버로 룩을 잡고, 묻지 않고 완주한다

**사용자에게 커버 후보를 고르게 하지 않는다.** 레퍼런스 질문(0단계) 이후 6장 전 과정에 사용자 선택 지점이 없다 — 완성된 6장을 받아보는 것이 사용자의 경험이다. 룩 판정은 사용자 대신 이 스킬이 전문 광고 기획자로서 한다.

커버를 먼저 뽑는 이유: 룩(팔레트·광질·타이포·제품 각도)의 기준점이 필요하고, 확정 비용이 가장 싼 지점에서 확정해야 한다. 절차:

1. **1번 커버를 1~2장 생성하고 직접 검수한다** — element의 제품이 실물 사진과 일치하는가, 한글 카피가 검수 루프 5항목을 통과하는가, (레퍼런스가 있으면) 레퍼런스의 룩과 정합하는가, 확정된 스토리의 무드가 맞는가. 어긋나면 프롬프트를 고쳐 재생성한다.
2. 통과한 커버의 룩을 기준 삼아 **나머지 5장을 장당 1장씩 생성**한다. 각 장도 같은 기준(한글 검수 루프 포함)으로 자체 검수하고, 미달인 장만 재생성한다.
3. 6장이 모이면 세트 일관성(팔레트 3색 · 광원 방향 · 타이포 성격 · 제품 각도)을 한 번 더 훑고 전달한다.

특정 장이 재시도 한도까지 기준 미달이면 억지로 반복하지 말고, 최선본을 넣되 전달 노트에 "이 장은 ○○가 아쉬워 재생성 1회면 개선 가능합니다"라고 한 줄 남긴다 — 크레딧을 태우는 것보다 정직한 보고가 낫다.

## 비율과 마감

- 비율은 1단계에서 확정한 값: 캐러셀 4:5(기본) / 정방 1:1 / 스토리 9:16. 6장 모두 동일 비율.
- 인쇄·고해상 필요 시 확정본만 upscale_image 4K (전 장 업스케일은 크레딧 낭비). 업스케일 후에도 한글이 뭉개지지 않았는지 한 번 더 확인한다.
- 전달 시: 완성형 6장 + 장별 카피 기록(수정·법무용) + 룩 설계 근거 한 줄(레퍼런스 반영 내용 또는 자체 설계 근거). "카피를 얹으세요" 안내는 하지 않는다 — 카피는 이미 들어가 있다. 카피 미포함 장이 있을 때만 그 장에 한해 후반 안내를 붙인다.
